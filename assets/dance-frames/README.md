# 원본 참조 프레임 애니메이션 — 시각 승인 전 시안

사용자가 제공한 6포즈 원화를 직접 참조하여 내장 이미지 생성 도구로 만들었다.
Rive 재작화보다 원본 인물·그림체에 가까운 대안이며, 원본 픽셀 그대로의 복제나
전문 애니메이터가 정리한 최종 원화라고 주장하지 않는다.

## 파일 / 재현

- `opening.png`: 손잡기 → 펼치기, 16개 셀
- `embrace.png`: 펼치기 → 가까이 안기, 16개 셀
- `turn.png`: 포옹 → 손 올리기 → 턴, 16개 셀
- `lift.png`: 포옹 → 무릎 준비 → 들어올리기, 16개 셀 (두 번째 생성본)
- `npm run dance:upscale`: Real-ESRGAN(`realesrgan-x4plus-anime`)으로 4장을 4배 확대해 `upscaled/`에 저장 (git 제외)
- `npm run dance:frames`: 원본 시트에서 셀 경계를 찾고 4배본에서 픽셀을 잘라 576px 셀·WebP 품질 60의 투명 atlas 5개 생성
- `FrameDanceActor.tsx`: 단일 canvas, DPR 최대 2, 필요한 atlas와 다음 atlas 로딩,
  스크롤 진행률로 직접 프레임 선택, 먼 페이지 메모리 해제

순서: opening → embrace → turn → turn 역순 → lift.
생성한 별도 복귀 시트는 두 사람이 순식간에 좌우를 바꾸어 제외했다.
첫 lift 시트도 신부 방향이 갑자기 바뀌어 제외했다. 최종 lift는 신부 머리를
계속 오른쪽에 유지하므로 원본 carry 구도의 좌우 방향과 다르다.
80 프레임 위치이지, 서로 다른 그림 80장을 제작한 것은 아니다.

## 생성 프롬프트 세트

방식: 내장 image_gen, 원본 6포즈 PNG + 직전 승인 후보 시트를 참조 이미지로 전달.
공통 조건: identity-preserve, 투명 배경의 4×4 스프라이트 시트, 같은 카메라/비율,
둥근 작은 얼굴·점 눈·입 없음·작은 코, 신랑의 검은 가르마 머리/검은 정장/흰 셔츠/
얇은 타이, 신부의 낮은 올림머리/홀터 드레스/긴 베일, 유기적인 검은 잉크 선,
얼굴과 드레스 내부 불투명 아이보리, 셀별 여백, 글자·숫자·격자·그림자 금지.

동작별 추가 조건:

1. opening: 원본 좌상단에서 시작. 무릎 준비 후 잡은 팔을 펼치며 벌어짐.
   신랑 자유 팔과 뒤쪽 발을 들어 원본 상단 중앙 자세로 도착.
2. embrace: 원본 상단 중앙에서 자유 팔·발을 내리고 잡은 팔을 굽혀 접근.
   신부는 가슴에 손, 신랑은 허리를 감싸 원본 우상단 포옹으로 도착.
3. turn: 포옹을 풀고 손을 잡아 올림. 신부가 손 아래로 회전하며 드레스/베일 후행.
   신랑 왼쪽, 신부 오른쪽 유지. 원본 우하단 턴으로 도착.
4. lift(최종): 신랑 왼쪽, 신부 머리는 모든 프레임에서 오른쪽 유지. 좌우 교체 금지.
   무릎을 굽혀 등과 무릎 아래를 받친 뒤 다리를 왼쪽으로 들어올림. 작은 동작 증가량,
   둘 다 팔 두 개, 카메라 회전/미러 플립 금지. 마지막에 안아든 자세로 안정화.

## 품질 검수 / 남은 제한

- 투명 여백의 밀도가 낮은 위치에서 셀을 분리해 불균등한 생성 그리드에 대응.
- 모든 프레임에 동일 확대율을 적용하고 바닥선을 정렬. 포즈마다 꽉 채워 확대하지 않음.
- 이미지 혼합은 얼굴·팔 잔상을 만들므로 사용하지 않음. 손그림 프레임 직접 재생.
- 실제 원본과 얼굴/헤어/드레스 윤곽의 미세한 차이가 남아 있다.
- 일부 중간 동작의 간격·그림 떨림은 전문적인 프레임 보정이 필요할 수 있다.
- 원본 셀 약 313px. 4배 업스케일 후 576px 셀로 써서 레티나(716px 표시)에서 선이 또렷하다.
  업스케일은 새 디테일을 그리지 않으며, 머리·정장의 연필/크레용 질감을 매끈한 검정으로 정리한다.
  atlas 합계 2.3MB(384px·q94) → 1.7MB(576px·q60). 디코딩 메모리는 장당 약 20MB(이전 9MB), 동시에 최대 3장.
- iOS Safari/카카오톡 인앱 실기기 테스트와 사용자 최종 시각 승인은 미완료.

기능 테스트 통과를 캐릭터 동일성 또는 부드러움의 보증으로 취급하지 않는다.
