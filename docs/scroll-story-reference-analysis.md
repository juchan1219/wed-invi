# End Speciesism 스크롤 연출 분석

조사 대상: [endspeciesism.org](https://endspeciesism.org/)

조사일: 2026-08-14

이 문서는 화면 인상만 기록한 것이 아니다. 데스크톱 1440×900, 모바일 390×844에서 직접 스크롤하고,
렌더링된 DOM·스타일·공개 Next.js 번들을 함께 확인해 구현 방식을 역추적한 결과다.

## 결론

레퍼런스의 완성도는 “큰 이미지를 스크롤에 맞춰 교체”해서 생기지 않는다. 하나의 긴 타임라인 안에서
배경, 인물, 표정, 소품, 종이 마스크, 글자와 카메라를 모두 독립 레이어로 움직이기 때문에 한 장면 안에서도
계속 새로운 사건이 일어난다.

현재 청첩장 스토리는 8개의 합성 이미지로 11개 비트를 만들고, 장면마다 이미지 한 장의 줌과 끝부분
크로스페이드만 수행한다. 이 구조로는 키프레임을 늘려도 레퍼런스 수준의 깊이와 연속성을 만들 수 없다.
따라서 자산 분리와 타임라인 엔진을 함께 교체해야 한다.

## 실제 구현 구조

### 1. 스크롤을 타임라인 시간으로 사용한다

공개 번들에는 Theatre.js 프로젝트 상태가 JSON으로 포함되어 있다. 각 레이어의 키프레임을
`position`, `rotation`, `scale`, `opacity`, `clip` 트랙으로 저장하며, 다음 방식으로 스크롤을 재생 위치에 연결한다.

```ts
sheet.sequence.position = window.scrollY / viewport.height
```

즉 “현재 장면 번호”를 구하는 대신, 문서 스크롤 1화면 높이를 타임라인 1단위로 사용한다. 위로 스크롤하면
같은 타임라인을 자연스럽게 역재생하고, 중간으로 점프하면 해당 시간의 모든 레이어 상태를 즉시 계산한다.

### 2. React가 아니라 DOM 스타일을 매 프레임 갱신한다

React는 레이어 구조만 렌더링한다. Theatre.js 값이 바뀔 때 각 노드에 아래 스타일을 직접 적용한다.

- `translate3d(...) rotate(...) scaleX(...) scaleY(...)`
- `opacity`와 `visibility`
- 네 꼭짓점을 독립적으로 움직이는 `clip-path: polygon(...)`
- 변경 속성에 맞춘 `will-change`

따라서 수백 개의 키프레임이 있어도 스크롤마다 React 트리를 다시 렌더링하지 않는다.

### 3. 합성 그림을 다시 자르는 대신 실제 레이어를 사용한다

확인된 자산에는 다음과 같은 분리 파일이 있다.

- 산과 하늘, 농장, 도로, 공장 내부·외부·항공 배경
- 트럭의 앞·뒤·옆 모습과 연기
- 개와 돼지의 표정·자세·꼬리
- 팔과 손, 말풍선, 의성어
- 밝은 종이·어두운 종이의 본문 질감과 찢어진 가장자리
- 시계판과 시곗바늘, 스케치 카드

같은 인물이 한 장면에 있어도 몸, 꼬리, 손, 말풍선이 별도 자산이다. 그래서 꼬리를 흔들면서 몸은
고정하거나, 손만 화면 밖에서 들어오거나, 표정만 교체하는 연출이 가능하다.

### 4. 장면 전환은 크로스페이드보다 공간 변형을 우선한다

직접 확인한 전환은 다음과 같다.

- 첫 풍경을 확대하며 트럭과 인물을 순차 등장
- 종이의 찢어진 가장자리가 화면을 밀어 올리며 다음 세계 공개
- 가로 패널의 `clip-path`가 벌어지며 내부 장면 노출
- 위·아래 장면이 동시에 보이는 분할 화면
- 작은 카드가 뷰포트를 채울 때까지 확대된 뒤 다음 배경으로 연결
- 동일한 구도의 이미지가 교체되며 시간과 장소가 점프하는 매치컷
- 밝은 종이에서 어두운 종이로 색과 질감이 전환되며 감정선 변화

페이드는 보조 수단이고, 대부분은 마스크·카메라·레이어 이동으로 앞 장면이 다음 장면의 일부가 된다.

### 5. 타이포그래피도 장면 레이어다

메인 타이틀은 하나의 텍스트 노드가 아니라 글자마다 SVG path가 있고, 각 글자에 별도 위치 키프레임이 있다.
본문 문장은 장면 상단에 고정해 읽을 시간을 확보하며, 말풍선과 의성어는 그림 안의 사건에 맞춰 크기와
투명도가 변한다.

### 6. 데스크톱과 모바일은 서로 다른 구도다

모바일은 데스크톱 이미지를 가운데로 자른 결과가 아니다.

- 데스크톱: 넓은 풍경, 좌우로 이동하는 피사체, 큰 가로 패널
- 모바일: 인물과 사건을 세로축에 재배치, 패널을 더 작게 시작해 세로 화면 안에서 확대
- 진행도: 데스크톱 우측 중앙, 모바일 우측 하단
- 내비게이션: 데스크톱 링크, 모바일 햄버거

동일한 타임라인 의미를 유지하되 레이어의 기준 위치와 크기는 브레이크포인트에 맞게 바뀐다.

### 7. Lenis는 입력을 부드럽게 하고, 타임라인이 연출을 담당한다

레퍼런스는 Lenis 1.1.2를 `requestAnimationFrame`으로 구동한다. 다만 높은 완성도의 핵심은 Lenis 자체가
아니라 분리 레이어와 키프레임 타임라인이다. 청첩장에는 네이티브 스크롤을 유지하고 타임라인 재생 헤드만
감쇠하는 편이 iOS·카카오톡 인앱 브라우저와 접근성에 더 안전하다.

## 현재 구현에서 직접 재현한 결함

1. 장면 교차 구간에 두 문구가 동시에 보이며 서로 겹친다.
2. 엽서 공개용 단색 사각형이 원본 일러스트를 크게 가린다.
3. 동일 합성 이미지를 마스크로 복제한 전경은 진짜 깊이 차이를 만들지 못한다.
4. `formatCeremonyTime()`이 서버에서 `PM`, 브라우저에서 `오후`를 반환해 hydration 오류가 발생한다.
5. 데스크톱에서도 스토리가 26rem 카드 폭에 갇혀 레퍼런스의 공간감이 사라진다.
6. 빠른 스크롤 중에는 한 장면의 사건이 충분히 읽히지 않고 이미지 교체처럼 느껴진다.

## 이 프로젝트에 적용할 원칙

- 합성 이미지 수를 늘리는 대신 움직여야 하는 대상을 분리한다.
- 하나의 연속된 재생 헤드를 모든 레이어가 공유한다.
- 페이드만으로 장면을 바꾸지 않고 종이 마스크, 확대, 패널, 매치컷을 사용한다.
- 모바일·데스크톱 좌표를 별도 튜닝한다.
- 첫 화면과 핵심 문구는 서버 HTML에 남긴다.
- reduced motion에서는 타임라인을 제거하고 대표 장면을 일반 콘텐츠로 제공한다.
- React state는 챕터 표시와 접근성 값처럼 저빈도 상태에만 사용한다.
