# 풀 일러스트 모바일 웨딩 스토리 설계

## 목표

`codex/doodle-wedding-story` 브랜치의 16숏 스토리를 첨부 기준 이미지와 같은 손그림 완성도로 전면 재제작한다.
캐릭터, 배경, 소품, 전경의 선 굵기와 채색 질감을 하나의 스타일 바이블로 통일하고,
장면 교체가 아니라 앞 장면의 시각 요소가 다음 장면을 만드는 연속 전환을 구현한다.

레퍼런스인 `endspeciesism.org`의 핵심은 그대로 따라야 한다.

- 하나의 스크롤 재생 헤드가 모든 레이어를 제어한다.
- 배경, 인물, 소품, 마스크, 타이포그래피를 독립 레이어로 움직인다.
- 페이드보다 카메라 이동, polygon 마스크, 종이 와이프, 패널 확장, 매치컷을 우선한다.
- 아래·위 스크롤과 큰 점프에서 같은 진행률은 항상 같은 화면을 만든다.

## 승인된 화면 전략

스토리 구도는 모바일 웹 크기로 고정한다.

- 논리 캔버스: `430 × 932`
- 원화 기준 크기: `1080 × 2340` 또는 장면에 필요한 동등 비율
- 실제 렌더링: `430 / 932` 비율을 유지한 채 `100vw × 100svh` 안에 contain
- 최대 렌더링 크기: `430 × 932`
- 데스크톱: 모바일 캔버스를 중앙에 배치하고 좌우는 미색 종이 여백으로 처리한다.
- 모바일: 안전 영역을 포함해 화면을 가득 채운다.

따라서 한 배경으로 모바일과 와이드 데스크톱을 모두 덮지 않는다. 각 장면은 세로 구도에 맞춰 생성하며,
숏 10–12는 동일한 프로포즈 3컷 원화의 왼쪽·가운데·오른쪽을 각각 크롭하고, 나머지 숏은 전용 세로 배경을 사용한다.
데스크톱 전용 좌표 트랙은 제거하고 하나의 모바일 좌표계만 사용한다. 캔버스는 비율을 유지해 확대·축소하며
남는 데스크톱 영역은 미색 여백으로 둔다. 원화 자체는 찌그러뜨리지 않는다.

## 스타일 바이블

첨부된 함부르크·반지·도쿄타워 3컷 이미지를 유일한 품질 기준으로 사용한다.

### 선과 질감

- 검은 마커 외곽선은 굵고 약간 흔들리며 완벽하게 반듯하지 않다.
- 채색은 색연필이나 크레용의 결이 보이며 일부 흰 종이가 남는다.
- 그림자와 광원은 최소화하고 검은 선, 제한된 색, 종이 여백으로 깊이를 만든다.
- 컴퓨터 도형처럼 완벽한 원, 직선, 균일한 그라데이션을 금지한다.

### 색상

- 종이: 미색 `#f7f1df`
- 잉크: 짙은 먹색 `#171717`
- 포인트: 코럴, 옅은 하늘색, 버터 노랑, 탁한 초록
- 한 장면에서 포인트 색은 세 가지 이하로 제한한다.

### 캐릭터 모델

- 예찬: 둥근 콩 몸, 검은 안경, 짧은 입, 장면에 따라 검은 재킷 또는 셔츠·넥타이
- 주은: 둥근 콩 몸, 점눈, 묶은 머리 또는 땋은 머리, 장면에 따라 재킷 또는 흰 원피스·베일
- 눈, 얼굴 폭, 몸 비율, 선 굵기, 안경과 머리 형태는 모든 숏에서 고정한다.
- 표정은 얼굴을 다시 그리는 대신 눈·입·팔 포즈가 바뀌는 방식으로 확장한다.

먼저 정면·측면·후면·웃음·놀람·웨딩 포즈를 포함한 마스터 캐릭터 시트를 만들고 승인 기준 자산으로 고정한다.
이후 모든 이미지 생성에는 이 시트와 첨부 3컷을 함께 참조한다.

## 자산 구조

각 숏은 완성 일러스트의 밀도를 가지면서도 전환에 필요한 대상을 분리한다.

```text
public/story/doodle-v2/
  style-guide.webp
  characters.webp
  01-opening/
    background.webp
    middle.webp
    couple.webp
    foreground.webp
  02-sidecar/
    ...
  ...
  16-invitation/
    ...
  manifest.ts
```

각 숏은 원칙적으로 다음 4–6개 레이어를 가진다.

1. 세로 배경 원화
2. 장소를 식별하는 중경
3. 예찬·주은 또는 주인공 소품
4. 전경 프레임
5. 장면 전환 마스크
6. 필요한 경우 표정·팔·반지·문 같은 교체 레이어

주요 배경과 인물은 CSS 도형으로 그리지 않는다. CSS는 배치, 마스크, 변형, 테두리와 종이 질감에만 사용한다.
현재 `DoodleScene`, CSS 콩 군중, CSS 예식장, CSS 사이드카는 새 원화 자산으로 교체한다.

## 16숏 콘티와 전환

### 1. 결혼 이야기 오프닝

제주 하늘, 오름, 바닷바람이 보이는 세로 원화 위로 제목 글자가 서로 다른 속도로 떨어진다.
전경 풀잎과 구름이 반대 방향으로 움직여 카메라 진입감을 만든다.

### 2. 사이드카 도착

사이드카가 화면 아래에서 들어오고 바퀴, 차체, 커플이 별도 속도로 움직인다.
도로가 길게 휘어지며 다음 숏의 시선 방향을 만든다.

### 3. 같은 방향

카메라가 커플 뒤쪽으로 접근한다. 화면을 가득 채운 코럴색 사이드카 덮개가 종이 와이프로 이어진다.

### 4. T타워 카드

코럴 종이가 찢어지며 작은 T타워 스케치 카드를 공개한다. 카드는 회전과 비균일 스케일로 세로 화면을 채운다.

### 5. 창문 안 회사 동료

카드의 한 창문으로 카메라가 진입하고 좌우 창틀이 밖으로 밀린다. 예찬과 주은은 같은 크기·선화의 정면 포즈다.

### 6. 어색한 책상

책상이 아래에서 올라오고 노트북·커피·시선이 순서대로 등장한다. 책상 상판이 다음 만화 패널의 아래 테두리가 된다.

### 7. 농담

창틀이 왼쪽 만화 패널로 변하고 예찬의 팔과 말풍선만 독립적으로 튀어나온다.

### 8. 웃음 참기

오른쪽 패널이 polygon 마스크로 열린다. 주은의 입과 팔 포즈가 두 단계로 바뀐다.

### 9. 함께 웃기

두 패널이 중앙에서 합쳐지고 웃음 효과선이 화면 전체로 확장된다. 코럴 효과선은 다음 3컷의 외곽선이 된다.

### 10. 함부르크 프로포즈

3컷 전체가 작은 카드로 등장한 뒤 왼쪽 패널까지 카메라가 확대된다. 항구 난간과 노을 전경을 분리한다.

### 11. 반지의 대답

카메라가 가운데 패널로 수평 이동한다. 반지 상자는 전경으로 확대되고 반짝임과 전구가 서로 다른 깊이로 움직인다.

### 12. 도쿄의 여름

오른쪽 패널로 이동하며 도쿄타워가 세로 화면을 채운다. 타워의 코럴 선이 아래로 늘어나 다음 숏의 예식장 아치를 그린다.

### 13. 예식장 도착

도쿄타워 선이 잠실 예식장 외곽선으로 변하고 문 앞의 평상복 커플이 뒤에서 걸어간다. 문은 닫힌 상태에서 시작한다.

### 14. 웨딩 매치컷

문이 열리는 순간 같은 실루엣의 평상복 커플이 웨딩 커플로 교체된다. 문짝은 화면 밖으로 밀리며 피날레 전경이 된다.

### 15. 모두의 도착

양쪽 하객과 전·중·후경 꽃가루가 서로 다른 속도로 들어온다. 카메라는 커플에게 천천히 접근한다.

### 16. 초대장 연결

베일과 미색 종이가 아래에서 올라와 장면 전체를 덮는다. 종이 표면과 실제 청첩장 본문의 배경색을 일치시켜
스크롤 스토리가 일반 콘텐츠로 끊김 없이 연결된다.

## 타임라인 엔진

기존 `storyTimeline.ts`를 유지하되 다음 상태를 추가한다.

```ts
type StoryLayerState = {
  x: number;
  y: number;
  scaleX: number;
  scaleY: number;
  rotate: number;
  opacity: number;
  originX: number;
  originY: number;
  clip?: Clip;
};
```

- 전체 레이어는 하나의 연속 진행률 `0..1`을 공유한다.
- 각 숏 사이에 앞·뒤 장면이 동시에 활성화되는 전환 구간을 둔다.
- 큰 점프는 현재 동작처럼 즉시 스냅하고, 작은 스크롤은 프레임 시간 기반 감쇠를 사용한다.
- 비활성 레이어는 DOM 스타일 갱신과 `will-change`를 중단한다.
- React state는 애니메이션 프레임에 사용하지 않는다.
- 네이티브 스크롤을 유지해 iOS와 카카오톡 인앱 브라우저의 기본 동작을 방해하지 않는다.

## 컴포넌트 경계

- `storyAssets.ts`: 자산 URL, 원화 크기, 크롭 기준, preload 여부
- `storyTimeline.ts`: 숏, 레이어, 키프레임과 전환 불변조건
- `StoryLayer.tsx`: 자산 타입에 따른 마크업만 렌더링
- `useStoryTimeline.ts`: 스크롤 측정, 샘플링, DOM 스타일 적용
- `WeddingStory.module.css`: 고정 모바일 캔버스, 계층, 마스크와 정적 스타일
- `StoryFallback.tsx`: 모션 축소 및 JavaScript 비활성 상태의 6장 정적 카드

## 접근성·성능

- 첫 문구, 16숏 전체 대본, 건너뛰기 링크는 서버 HTML에 남긴다.
- 애니메이션 텍스트는 스크린리더에서 숨겨 중복 읽기를 방지한다.
- `prefers-reduced-motion`에서는 sticky 타임라인을 숨기고 대표 원화 6장을 문서 흐름으로 보여준다.
- 배경은 WebP, 투명 레이어는 alpha WebP로 저장한다.
- 첫 장면만 eager 로드하고 나머지는 장면 접근 전에 lazy preload한다.
- 원본 사진과 생성 원본 PNG는 공개 경로에 두지 않는다.

## 검증 기준

### 자동 검증

- 16숏과 챕터 경계가 연속적이다.
- 각 숏에는 배경, 인물 또는 소품, 전환 가능한 전경이 있다.
- 모든 자산이 `manifest.ts`에 등록되고 실제 파일 크기와 원화 크기가 일치한다.
- scaleX/scaleY, origin, clip 트랙이 역방향에서도 같은 값을 반환한다.
- `npm run test:story`, `npm run typecheck`, `npm run build`, `git diff --check`가 통과한다.

### 브라우저 검증

- 390×844, 430×932, 1280×720에서 같은 모바일 구도가 유지된다.
- 16숏 각각 시작·중간·종료 화면을 캡처해 스타일 바이블과 대조한다.
- 모든 장면 경계를 아래·위 스크롤로 통과한다.
- 첫 화면에서 마지막 화면, 마지막에서 중간으로 큰 점프한다.
- 새로고침·뒤로가기 스크롤 복원에서 빈 장면이 없다.
- `/`, 잘못된 `/i/<token>`, `/admin/login`에 콘솔 오류나 hydration 오류가 없다.

## 완료 조건

- CSS로 임시 제작한 주요 배경과 캐릭터가 남아 있지 않다.
- 모든 숏의 캐릭터 모델, 선 굵기, 색, 종이 질감이 첨부 기준 이미지와 일치한다.
- 모든 장면 경계에서 크로스페이드가 아닌 공간적 연결이 확인된다.
- 모바일 고정 캔버스가 데스크톱과 모바일에서 잘리거나 늘어나지 않는다.
- 자동 검증과 브라우저 검증 항목이 모두 증거로 남는다.
