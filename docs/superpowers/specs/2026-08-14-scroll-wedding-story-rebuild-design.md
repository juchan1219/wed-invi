# 예찬 · 주은 스크롤 웨딩 스토리 전면 재구축 디자인

## 목표

레퍼런스와 같은 수준의 연속적인 스크롤 연출을 밝고 유쾌한 웨딩 스토리로 재해석한다. 사용자는 약
45~60초 동안 아래로 스크롤하며 배경, 카메라, 인물 표정, 소품과 종이 레이어가 하나의 타임라인 위에서
이어지는 2.5D 이야기를 본다. 위로 스크롤하면 동일한 상태를 자연스럽게 역재생한다.

레퍼런스의 캐릭터나 장면을 복제하지 않는다. 분리된 투명 레이어, 키프레임 타임라인, 찢어진 종이 전환,
패널 확대, 매치컷과 반응형 재구성이라는 제작 기법만 적용한다.

기술 조사 근거는 [`docs/scroll-story-reference-analysis.md`](../../scroll-story-reference-analysis.md)에 있다.

## 성공 기준

- 화면을 단순한 합성 이미지 교체가 아니라 연속된 한 편의 애니메이션으로 느낀다.
- 최소 6개 챕터와 16개 숏이 있고, 숏 안에서도 2개 이상의 시각 변화가 발생한다.
- 최소 24개의 독립 시각 레이어와 100개 이상의 의도적인 키프레임을 사용한다.
- 크로스페이드 외에 종이 찢김, polygon reveal, 카메라 이동, 패널 확대, 매치컷을 모두 사용한다.
- 390×844 모바일과 1440×900 데스크톱에서 각각 조정된 구도로 확인된다.
- 아래/위 스크롤, 빠른 점프, 새로고침 후 복원에서 빈 화면이나 겹친 문구가 없다.
- hydration 오류와 콘솔 오류가 없다.
- reduced motion, 키보드 건너뛰기, 의미 있는 읽기 순서를 제공한다.
- 기존 기본·개인화 청첩장과 공유·보안 규칙은 유지한다.

## 경험의 구조

스토리는 약 `1,850svh`를 사용한다. 모바일에서 약 15,600px, 데스크톱에서 약 16,600px의 재생 공간이다.
스크롤 속도에 따라 체감 시간은 달라지지만 보통 속도에서 45~60초를 목표로 한다.

데스크톱에서는 스토리만 100vw 전체 화면으로 확장한다. 스토리가 끝나면 기존 26rem 청첩장 본문으로
종이 한 장이 접히듯 이어진다. 모바일에서는 처음부터 전체 너비를 사용한다.

## 콘티: 6개 챕터, 16개 숏

### 1. 같은 방향을 바라보기 시작한 날 — 0~15%

1. 제주 바다와 유채꽃이 배경·중경·전경 3단으로 열린다. 종이 조각처럼 생긴 제목 글자가 한 글자씩
   제자리에 내려앉고 `예찬과 주은의 결혼 이야기`가 완성된다.
2. 사이드카 오토바이가 화면 아래에서 올라온다. 바퀴는 회전하고 차체와 두 사람은 서로 다른 폭으로
   흔들린다. 전경 유채꽃은 더 빠르게 스쳐 지나간다.
3. 두 사람이 서로 보다가 앞을 바라본다. 이름표가 손그림 선을 따라 나타나고 제목 글자는 위로 흩어진다.

### 2. 처음엔 그냥 회사 동료 — 15~33%

4. 밝은 종이의 찢어진 가장자리가 아래에서 올라오며 제주 장면을 덮는다. 작은 T타워 카드가 중앙에
   나타나고 화면을 가득 채울 때까지 확대된다.
5. 카메라는 건물 외벽의 한 창문으로 들어간다. 외벽은 양옆으로 밀리고 사무실 배경과 두 사람의
   독립 컷아웃이 등장한다.
6. 두 사람 사이의 빈 공간, 노트북과 커피가 차례로 놓인다. 시선이 살짝 엇갈리며
   `아주 조금… 어색한 동료였죠.`가 종이 라벨에 적힌다.

### 3. 웃음을 참는 데 실패했습니다 — 33~52%

7. 화면이 두 개의 비뚤어진 만화 패널로 갈라진다. 예찬이 몸을 기울이며 작은 말풍선을 밀어 넣는다.
8. 주은의 표정이 무표정 → 볼을 부풀린 웃음 참기 → 눈을 감은 폭소로 두 번 교체된다. 말풍선은
   찌그러지고 `푸핫!` 글자가 화면 밖까지 커진다.
9. 두 패널이 하나로 합쳐지며 두 사람이 같이 웃는 넓은 장면이 된다. 배경 채도는 올라가고
   `평생 웃겨주고 웃어주는 짝꿍` 문구가 남는다.

### 4. 우리의 길은 이어졌습니다 — 52~70%

10. 실제 사진을 참고해 그린 함부르크 엘브필하모니 프로포즈, 반지를 보여주는 주은, 도쿄타워 웨딩스냅
    세 장면이 찢어진 종이 프레임 안에서 한 장씩 펼쳐진다. 원본 사진은 공개 경로에 복사하지 않는다.
11. 점선 경로가 세 장면을 연결한다. 모바일에서는 프로포즈 → 반지 → 도쿄타워를 숏마다 좌·중·우로
    이동해 각 장면을 화면 가득 보여주고, 데스크톱에서는 세 장면의 관계를 한눈에 보여준다.
12. 도쿄타워 장면이 확대되며 `우리의 다음 장면` 문구와 예식장으로 이어지는 카메라 매치가 만들어진다.

### 5. 우리가 향한 곳 — 70~86%

13. 도로 끝에 잠실 아펠가모 입구가 나타난다. 두 사람의 어깨 너머 구도에서 카메라가 앞으로 이동하고,
    문이 좌우로 열리며 예식 날짜와 장소가 보인다.
14. 입구를 통과하는 순간 찢어진 세로 종이 띠가 위로 벗겨진다. 같은 자세의 캐주얼 의상이 브라운 수트와
    화이트 드레스로 교체되는 매치컷이다.

### 6. 우리 결혼합니다 — 86~100%

15. 가족·친구의 실루엣과 강아지가 양옆에서 들어온다. 꽃가루는 깊이에 따라 크기와 낙하 속도가 다르고,
    `예찬 ♥ 주은` 글자가 손으로 쓴 선을 따라 그려진다.
16. `우리 결혼합니다!!`가 크게 나타난 뒤, 아이보리 초대장 종이가 아래에서 올라와 화면을 덮는다.
    종이의 상단이 청첩장 본문의 실제 첫 부분과 정확히 연결되고 sticky가 해제된다.

## 시각 자산 시스템

기존 `-v2.webp` 그림은 캐릭터 외형, 복장, 색감과 분위기의 기준이자 reduced-motion 대표 컷으로 유지한다.
움직이는 장면에는 다음과 같은 투명 또는 분리 자산을 새로 만든다.

### 배경 7개

- 제주 하늘·섬·바다·유채꽃밭을 분리할 수 있는 와이드 배경
- T타워 외벽
- 사무실 내부
- 대화 장면의 단순화된 사무실 배경
- 제주 주행 배경
- 잠실 아펠가모 입구
- 결혼식 피날레 배경

### 인물·탈것 11개 이상

- 캐주얼 예찬: 정면, 기울여 말하기, 웃기
- 캐주얼 주은: 무표정, 웃음 참기, 폭소
- 커플 투샷: 오토바이 측면·후면
- 웨딩 예찬·주은 독립 컷아웃
- 오토바이 본체와 회전 가능한 앞·뒤 바퀴

### 소품·전환 8개 이상

- 노트북, 커피, 말풍선, 의성어
- 엽서 종이 프레임 3종과 점선 경로
- 실제 사진을 참고해 동일 화풍으로 재구성한 프로포즈 3단 장면
- 밝은 종이 질감과 찢어진 위·아래 가장자리
- 세로 종이 띠와 꽃가루 조각

이미지 안에 설명 문구를 굽지 않는다. 제목과 본문은 HTML/SVG로 렌더링한다. 투명 컷아웃은 실제 alpha를
보존한다. 긴 변은 2,400px 이하로 최적화하고 Next Image가 AVIF/WebP와 `srcset`을 제공하게 한다.

## 타임라인 엔진

### 데이터 모델

`storyTimeline.ts`는 장면과 렌더링을 모르는 순수 데이터다.

```ts
type StoryFrame = {
  at: number;
  x?: number;
  y?: number;
  scale?: number;
  rotate?: number;
  opacity?: number;
  clip?: readonly [number, number, number, number, number, number, number, number];
  ease?: "linear" | "easeIn" | "easeOut" | "easeInOut" | "hold";
};

type LayerTrack = {
  id: string;
  frames: readonly StoryFrame[];
  mobile?: readonly StoryFrame[];
  desktop?: readonly StoryFrame[];
};
```

`at`은 전체 스토리의 0~1 위치다. 키프레임 사이 값은 속성별로 보간한다. `hold`는 표정 스프라이트처럼
다음 프레임 직전까지 기존 값을 유지한다. 모바일·데스크톱 오버라이드는 같은 의미의 타임라인에서 좌표와
크기만 바꾼다.

### 런타임

1. 컨테이너의 시작점과 이동 가능 높이로 목표 진행률을 계산한다.
2. 스크롤 이벤트는 목표값만 저장하고 `requestAnimationFrame`을 예약한다.
3. 현재 재생 헤드는 프레임 간 시간에 기반한 지수 감쇠로 목표값을 따라간다.
4. 빠른 점프가 0.18 이상이면 즉시 목표로 이동해 빈 중간 화면을 방지한다.
5. 각 레이어 트랙을 샘플링해 `translate3d`, `rotate`, `scale`, `opacity`, `clip-path`를 직접 적용한다.
6. React state는 현재 챕터가 달라질 때와 ARIA 진행률을 저빈도로 갱신할 때만 사용한다.

초기 마운트, `pageshow`, `resize`, `orientationchange`에서 즉시 다시 계산해 스크롤 복원과 회전을 처리한다.

### 타임라인 불변 조건

- 모든 트랙의 `id`는 고유하다.
- 각 트랙 프레임은 `at` 오름차순이며 0~1 범위다.
- 모든 장면에는 적어도 하나의 시각 레이어와 하나의 읽을 수 있는 문구가 있다.
- 0~1 전체 구간에 불투명한 배경 레이어가 적어도 하나 존재한다.
- 문구의 노출 구간은 서로 겹치지 않는다.

- `useStoryTimeline.ts`: 스크롤/리사이즈 이벤트와 rAF 재생 헤드
- `timelineMath.ts`: 보간, easing, 트랙 샘플링 순수 함수
- `storyTimeline.ts`: 키프레임과 챕터 데이터
- `StoryLayer.tsx`: 정적 이미지·HTML 레이어의 일관된 DOM 계약
- `StoryFallback.tsx`: reduced-motion 및 JS 없는 읽기 가능한 대체 콘텐츠
- `WeddingStory.module.css`: 무대, 반응형 기본 구도, 종이 질감과 장식

## 날짜 hydration 오류

원인은 `Intl.DateTimeFormat("ko-KR")`의 `dayPeriod` 문자열이 서버 ICU에서는 `PM`, 브라우저에서는 `오후`로
달라지는 것이다. 서울 기준 시·분 숫자만 `hourCycle: "h23"`으로 구한 뒤 오전/오후를 코드에서 결정한다.
사용자의 로캘과 무관하게 서버·브라우저가 같은 문자열을 만든다.

## 접근성과 대체 경험

- 무대 전체는 `aria-label="예찬과 주은의 결혼 이야기"`인 section이다.
- 움직이는 레이어는 장식이므로 빈 alt 또는 `aria-hidden`을 사용하고, 이야기는 별도 HTML 문구로 읽힌다.
- `이야기 건너뛰기`는 항상 키보드로 접근 가능하며 실제 본문 앵커로 이동한다.
- 진행도는 6개 챕터 이름과 현재 위치를 제공한다.
- `prefers-reduced-motion: reduce`에서는 sticky와 타임라인을 제거하고 대표 장면 6장을 일반 문서 순서로 보여준다.
- JS가 실패해도 첫 장면, 제목, 핵심 문구와 건너뛰기 링크가 보인다.

## 성능 기준

- 첫 화면 자산만 `preload`; 나머지는 브라우저가 스토리에 진입할 때 요청한다.
- 정적 이미지에는 고정 크기 또는 fill 부모의 명확한 비율을 제공한다.
- 투명 자산을 포함한 스토리의 초기 네트워크 전송량은 모바일 기준 4MB 이하를 목표로 한다.
- 레이어는 `transform`, `opacity`, `clip-path`만 프레임마다 변경한다.
- `filter`와 큰 `backdrop-filter`의 연속 애니메이션은 사용하지 않는다.
- 오프스크린 스토리에서는 rAF 루프를 멈춘다.
