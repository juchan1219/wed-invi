# 7장면 웨딩 스토리 재구성 설계

## 목표

현재 16숏 스크롤 스토리를 사용자가 기억하기 쉬운 7개의 서사 장면으로 재구성한다.
화면 전환의 밀도는 유지하되 문구와 사건을 단순화하고, 제주에서 시작해 회사 동기·웃음·여행·결혼식으로 이어지는 흐름을 명확히 한다.

이 변경은 캐릭터나 화풍의 재디자인이 아니다. 현재 승인된 예찬·주은 콩 캐릭터, 굵고 흔들리는 검은 외곽선,
미색 종이, 색연필·크레용 결이 남는 제한 채색을 그대로 사용한다.

## 확정된 접근

사용자에게 보이는 서사는 7장면으로 구성한다. 애니메이션 구현에서는 장소 이동과 매치컷에 필요한 내부 비트를 둘 수 있지만,
대본·진행 안내·접근성 transcript는 7장면만 노출한다. 기존 16숏의 좋은 원화와 전환은 폐기하지 않고 새 7장면 아래에 재배치한다.

- 논리 캔버스 `430 × 932`와 데스크톱 중앙 contain 전략을 유지한다.
- 하나의 스크롤 진행률과 결정론적 역방향·점프 동작을 유지한다.
- 단순 풀프레임 페이드보다 종이 와이프, 카메라 진입, 패널 이동, 선 연결, 문 매치컷을 사용한다.
- 첫 화면과 마지막 화면은 기존 청첩장 본문에 자연스럽게 연결한다.

## 스타일 연속성

### 캐릭터

- 기존 `characters.webp`와 현재 장면별 예찬·주은 스프라이트를 그대로 재사용한다.
- 예찬의 검은 안경, 짧은 입, 둥근 콩 몸과 주은의 점눈, 묶거나 땋은 머리, 둥근 콩 몸을 바꾸지 않는다.
- 새 포즈가 필요하면 기존 캐릭터 시트의 얼굴·몸 비율·선 굵기를 유지한 파생 포즈만 만든다.
- 회사 장면은 현재 오피스 캐릭터, 여행 장면은 현재 캐주얼 캐릭터, 피날레는 현재 웨딩 캐릭터를 사용한다.

### 배경과 채색

- 배경은 미색 종이 위에 굵은 검은 선과 색연필 채색이 보이는 현재 스타일을 유지한다.
- 코럴, 옅은 하늘색, 버터 노랑, 탁한 초록을 중심으로 장면당 포인트 색을 세 가지 이하로 제한한다.
- 완벽한 벡터 직선, 균일한 그라데이션, 매끈한 3D 광택을 추가하지 않는다.
- 새 서울 연결 원화가 필요하면 현재 도쿄타워·예식장 원화와 같은 선 굵기와 종이 질감으로 제작한다.

## 7장면 콘티와 확정 문구

### 1. 제주 오프닝

제주 하늘, 오름, 바닷바람이 보이는 기존 오프닝 원화가 열린다. 제목 글자는 종이 조각처럼 들어오고,
전경 풀잎과 구름은 서로 다른 속도로 움직인다.

> 예찬과 주은의 결혼 이야기

### 2. 같은 방향을 바라보는 두 사람

예찬과 주은이 기존 사이드카 오토바이를 함께 타고 한 방향으로 달린다. 두 사람, 차체, 앞·뒤 바퀴, 도로를 분리해
약한 깊이감을 주며 카메라는 뒤에서 천천히 가까워진다. 이 장면에는 별도 본문 문구를 넣지 않는다.

### 3. 회사 동기

사이드카의 코럴 면이 종이 와이프로 바뀌고 SK T타워 카드가 나타난다. 카메라가 타워 창문을 통과하면
사무실 안에서 두 사람이 조금 떨어져 어색하게 서서 일하고 있다. 노트북과 책상 소품은 기존 오피스 원화를 재사용한다.

> 처음엔 회사 동기였던 두 사람

### 4. 농담과 웃음

예찬이 주은을 바라보며 농담하는 팔·입 포즈로 바뀐다. 주은은 웃음을 참는 중간 표정 없이 곧바로 배를 잡고
까르르 웃는 포즈로 전환한다. 말풍선이나 의성어 대신 표정, 팔, 웃음 효과선으로 농담을 표현한다.

> 예찬의 재미난 농담에 주은은 배꼽이 빠질 뻔했던 적이 한두 번이 아니었습니다.

### 5. 평생의 짝꿍

웃음 효과선이 여행 사진 카드의 테두리가 된다. 이 장면은 두 개의 연속 내부 비트로 구성한다.

1. 함부르크 엘브필하모니 프로포즈 사진과 반지를 보여주는 사진을 차례로 이동한다.

   > 그렇게 평생 웃겨주고 웃어주는

2. 도쿄타워 앞 웨딩스냅으로 수평 이동하고 타워의 코럴 선을 강조한다.

   > 짝꿍이 되기로 했습니다.

### 6. 서울로 돌아와 결혼식장으로

도쿄타워의 코럴 선이 아래로 이어져 서울의 길과 잠실 아펠가모 입구 선을 그린다. 두 사람은 평상복으로 입구까지 걸어가고,
문이 열리는 순간 같은 위치와 실루엣에서 예찬의 턱시도와 주은의 웨딩드레스로 매치컷한다.

> 2026.12.19 오후 12시 30분,  
> 잠실 아펠가모에서요!

날짜·시간·장소는 하드코딩하지 않고 `src/config/wedding.ts`의 `ceremony`와 `venue`에서 가져온다.
현재 설정값은 `2026-12-19T12:30:00+09:00`, `잠실 아펠가모`, `2층 단독홀`이며 청첩장, 지도, 캘린더,
공유 정보와 동일한 값을 사용한다.

### 7. 하객들과 함께하는 결혼식

턱시도를 입은 예찬과 웨딩드레스를 입은 주은이 중앙에 서고, 양쪽에서 하객과 꽃가루가 서로 다른 속도로 들어온다.
마지막에는 베일과 미색 종이가 올라오며 실제 청첩장 본문 배경으로 연결된다.

> 예찬 ♥ 주은  
> 소중한 분들과 함께,  
> 우리 결혼합니다!!

## 전환 구조

7개의 서사 장면은 다음 공간 연결을 사용한다.

1. 제주 제목 조각 → 사이드카 도로
2. 사이드카 코럴 면 → T타워 종이 와이프
3. T타워 창문 → 사무실 카메라 진입
4. 웃음 효과선 → 함부르크·도쿄 여행 카드 테두리
5. 도쿄타워 코럴 선 → 서울 길·잠실 아펠가모 입구
6. 예식장 문 → 평상복·웨딩복 실루엣 매치컷
7. 베일·미색 종이 → 일반 청첩장 본문

각 경계에는 앞 장면과 다음 장면의 공간 요소가 동시에 보이는 짧은 구간을 둔다. 같은 진행률은 정방향, 역방향,
큰 점프에서 항상 같은 레이어 상태를 만들어야 한다.

## 자산 사용 계획

### 그대로 재사용

- 제주 오프닝 배경과 섬·구름·제목 원화
- 사이드카, 앞·뒤 바퀴, 캐주얼 커플 스프라이트
- T타워 카드, 사무실 배경·책상·오피스 캐릭터
- 농담·웃음 캐릭터와 웃음 효과선
- 함부르크 프로포즈, 반지, 도쿄타워 여행 원화
- 예식장 외부·내부·문, 하객, 웨딩 커플, 베일·꽃가루 원화

### 새로 만들거나 보강할 수 있는 자산

- 도쿄타워 선에서 서울 길과 잠실 아펠가모로 이어지는 연결 원화 또는 투명 오버레이
- 기존 포즈만으로 배를 잡고 웃는 동작이 충분하지 않을 때의 주은 파생 포즈

새 자산은 기존 캐릭터 시트와 현재 완성 원화를 함께 참조한다. 기존 캐릭터의 얼굴이나 신체 모델을 새로 해석하지 않는다.

## 코드 구조

- `storyTimeline.ts`: 7개 공개 장면, 내부 애니메이션 비트, 레이어 키프레임과 전환 불변조건
- `storyAssets.ts`: 재사용 자산과 새 서울 연결 자산 등록
- `StoryFallback.tsx`: 7장면 중 대표 원화로 구성한 비모션 대체 화면과 새 대본
- `WeddingStory.tsx`: 7장면 transcript와 진행 안내
- `WeddingStory.module.css`: 기존 고정 모바일 캔버스와 종이 질감 유지
- `src/config/wedding.ts`: 날짜·장소의 단일 출처. 현재 값이 승인 내용과 일치하므로 불필요한 변경을 하지 않는다.

## 접근성·성능

- 서버 HTML에는 7장면 전체 대본과 이야기 건너뛰기 링크를 남긴다.
- 애니메이션 장면 문구는 스크린리더에서 숨겨 중복 읽기를 막는다.
- `prefers-reduced-motion`에서는 sticky 타임라인을 실행하지 않고 7장면을 대표하는 정적 카드 흐름을 제공한다.
- 첫 장면의 필수 배경·캐릭터만 즉시 로드하고 나머지는 지연 로드한다.
- 기존 `430 × 932` 논리 캔버스와 데스크톱 미색 여백을 유지한다.

## 검증 기준

### 자동 검증

- 공개 장면은 정확히 7개이며 순서와 문구가 이 문서와 일치한다.
- 날짜와 장소 문구는 `wedding` 설정에서 생성된다.
- 모든 내부 비트에 불투명 배경과 필요한 인물·소품 레이어가 있다.
- 6개 장면 경계가 정방향·역방향·큰 점프에서 결정론적이다.
- 기존 캐릭터 자산 ID와 스프라이트 크롭이 바뀌지 않는다.
- reduced-motion에서는 타임라인 관찰자와 애니메이션 프레임을 만들지 않는다.
- `npm run test:story`, `npm run typecheck`, `npm run build`, `git diff --check`가 통과한다.

### 브라우저 검증

- 390×844, 430×932, 1280×720에서 7장면의 시작·중간·끝을 확인한다.
- 사이드카 인물, 회사 장면 인물, 여행 사진, 웨딩 커플이 잘리지 않는다.
- 각 장면 경계를 아래·위 스크롤로 통과해 빈 화면과 이전 transform 잔류가 없는지 확인한다.
- 새로고침 42%·82%, 큰 점프, 뒤로·앞으로 복원에서 같은 장면이 유지된다.
- 기존 캐릭터 얼굴·몸 비율과 색연필 채색 스타일이 모든 장면에서 일관된다.
- `/`, 잘못된 `/i/<token>`, `/admin`에서 애플리케이션 콘솔 오류가 없다.

## 완료 조건

- 사용자에게 보이는 스토리는 승인된 7장면과 확정 문구만 사용한다.
- “짝꿍이 되기로 했습니다.”가 정확히 표시된다.
- 예찬·주은은 기존 승인 캐릭터와 동일하다.
- 모든 배경과 새 연결 원화가 기존 색연필 채색 스타일을 유지한다.
- 날짜·시간·장소가 청첩장 전체에서 `2026.12.19 오후 12시 30분 · 잠실 아펠가모`로 일치한다.
- 자동 검증과 브라우저 검증 증거를 새 7장면 기준으로 갱신한다.
