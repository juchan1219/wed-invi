# 예찬 · 주은 스크롤 웨딩 스토리 디자인

## 목표

기존 모바일 청첩장 앞에 45~60초 분량의 스크롤 스토리를 배치한다. 사용자가 아래로 스크롤하면 동화책과 짧은 애니메이션 사이의 감각으로 장면, 표정, 카메라 거리와 문구가 연속적으로 변하고, 위로 스크롤하면 자연스럽게 역재생된다.

레퍼런스의 특정 캐릭터나 화면을 복제하지 않는다. 종이 질감, 강한 색면, 여러 카메라 구도, 고정 무대 위 레이어 전환, 스크롤 스크럽이라는 시각 문법만 가져오고 예찬과 주은의 이야기로 새로 제작한다.

## 감정선과 러닝타임

- 전체 11샷, 보통 속도 스크롤 기준 45~60초
- 초반 3초 안에 두 사람, 결혼 이야기, 스크롤 방식이 보인다.
- 감정선: 어색한 회사 동료 → 예찬의 장난 → 주은이 웃음을 참음 → 함께 웃음 → 평생의 짝꿍 → 같은 방향 → 결혼식
- 오토바이는 도입, 방향 전환, 제주 여행에서만 강조한다. 반복되는 주행 화면은 만들지 않는다.
- 모든 문구는 2줄 이내로 유지한다.

## 11개 샷

1. 푸른 초원과 뭉게구름의 넓은 화면. 사이드카 오토바이를 탄 두 사람이 작게 등장하며 `예찬과 주은의 결혼 이야기`와 스크롤 힌트가 보인다.
2. 인물 2샷. 서로 바라보던 주은과 예찬이 스크롤에 맞춰 앞을 본다. 손그림 화살표와 이름표가 나타난다.
3. 을지로 SK T타워의 창문을 클로즈업했다가 건물 전체로 줌아웃한다. `처음엔 그냥 회사 동료였습니다.`
4. 어색하고 반듯하게 앉은 회사 동료 시절의 투샷. 여백과 작은 시선 움직임으로 어색함을 유머로 사용한다.
5. 예찬이 장난을 건다. 주은이 웃음을 참다가 두 사람이 동시에 크게 웃는 3단 표정 전환을 한 화면 안에서 스크럽한다.
6. 웃음이 잦아든 얼굴 클로즈업. `평생 웃겨주고 웃어주는 짝꿍으로 지내기로 했습니다.`
7. 찢은 종이 형태의 3칸 엽서가 순서대로 펼쳐진다: 제주도 → T타워 → 잠실 아펠가모.
8. 제주 초원을 달리는 사이드카 측면 롱숏. 전경 풀과 구름이 서로 다른 속도로 움직인다.
9. 두 사람의 어깨 너머로 잠실 아펠가모 입구가 가까워진다. `2026.12.19 오후 12시 30분, 잠실 아펠가모에서요!`
10. 같은 자세의 캐주얼 복장이 웨딩드레스와 브라운 수트로 바뀌는 매치컷.
11. 두 사람의 뒷모습 앞으로 가족과 친구들, 강아지 한 마리가 축하한다. 꽃가루와 팡파레가 터지고 `우리 결혼합니다!!`가 나타난 뒤 종이 레이어가 올라와 청첩장 본문으로 이어진다.

## 비주얼 시스템

- 1990~2000년대 미국 TV 카툰 문법을 현대적으로 재해석한 독창적인 2D 일러스트. 납작한 색면, 쐐기형 얼굴, 각진 팔다리, 굵고 불규칙한 외곽선, 과장된 키프레임 표정을 사용한다. 특정 기존 캐릭터나 프랜차이즈를 복제하지 않는다.
- 색상은 하늘색, 초원색, 유채꽃 노랑을 기본으로 하고 T타워는 청회색, 피날레는 코랄과 주황을 추가한다.
- 캐릭터는 제공된 세 장의 커플 사진을 인상착의 기준으로 한다. 예찬은 검은색 가르마 머리와 넓은 웃음, 주은은 검은 머리를 묶은 인상과 가는 눈매를 유지하되 초상화처럼 사실적으로 묘사하지 않는다.
- 1~9샷은 캐주얼 여행복, 10~11샷은 사진 속 브라운 수트와 홀터넥 화이트 드레스의 특징을 반영한다.
- 문자는 이미지에 굽지 않고 HTML로 올려 선명도와 접근성을 보장한다.

## 인터랙션

- 하나의 긴 컨테이너 안에 `100svh` 고정 무대를 두고 문서 스크롤 진행률을 0~1로 정규화한다.
- 진행률에 따라 장면을 크로스페이드하고, 같은 장면 내부에서는 줌·크롭·이동·표정 레이어를 연속 보간한다.
- 배경, 중경, 인물, 전경을 분리해 최대 3단 패럴랙스를 사용한다.
- 우측 상단에 가느다란 진행도와 `이야기 건너뛰기`를 둔다. 건너뛰기는 개인화 편지 시작점 또는 편지가 없으면 일정 섹션으로 이동한다.
- 사용자가 위로 스크롤하면 모든 효과가 역방향으로 재생된다.
- `prefers-reduced-motion`에서는 고정 스크럽을 제거하고 핵심 장면 4장을 일반 세로 콘텐츠로 보여준다.
- JavaScript가 실패해도 핵심 문구와 한 장의 대표 이미지는 보인다.

## 기존 청첩장과 연결

스토리 다음 순서는 개인화 편지 → 예식 일시·D-day·캘린더 → 갤러리 → 지도 → 계좌 → 연락처 → 방명록 → 공유다. `/`와 `/i/[token]`은 계속 같은 `Invitation` 컴포넌트를 사용하며 개인화 링크 공유 금지 등 기존 보안·공유 규칙은 변경하지 않는다.

## 성능·품질 기준

- 모바일 390×844를 우선 설계하고 320px부터 데스크톱 카드 폭까지 깨지지 않게 한다.
- 첫 장면만 우선 로드하고 나머지는 가까워질 때 디코딩한다.
- 정적 이미지에는 명시적 크기를 둬 레이아웃 이동을 방지한다.
- 스크롤 이벤트는 `requestAnimationFrame`으로 합치며 React state를 매 프레임 갱신하지 않고 CSS 변수와 DOM 속성을 갱신한다.
- 키보드 포커스, 충분한 색 대비, 의미 있는 대체 텍스트를 제공한다.

## 완료 기준

- 11샷의 내용과 감정선이 스크롤 순서대로 확인된다.
- 아래/위 스크롤, 빠른 점프 스크롤, 새로고침 후 스크롤 복원에서 화면이 비지 않는다.
- reduced motion과 건너뛰기가 동작한다.
- 기본 및 개인화 청첩장의 기존 기능이 유지된다.
- `npm run typecheck`와 `npm run build`가 통과하고 모바일 브라우저에서 시각 검수를 마친다.
